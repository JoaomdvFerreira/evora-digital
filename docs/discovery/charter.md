# Évora Digital Charter

**Version:** 0.1  
**Status:** Baseline draft  
**Date:** 2026-08-10

## 1. Mission

Évora Digital identifies concrete problems affecting people who live, work, study, conduct economic activity, provide services, or visit Évora, and creates open digital public goods when there is sufficient evidence that technology can produce a real and measurable improvement.

## 2. Programme objectives

Évora Digital exists to:

1. build structured and verifiable knowledge about needs in Évora;
2. identify problems where software has meaningful causal leverage;
3. avoid duplicating services, systems, or datasets that already exist;
4. validate assumptions through small experiments before investing in products;
5. produce open-source and reusable software when development is justified;
6. progressively improve the discoverability and reuse of civic data;
7. lower the barrier for students, developers, businesses, associations, researchers, and public bodies to create additional digital value for Évora;
8. use real projects as external dogfood for AIQT without allowing AIQT needs to determine what gets built.

## 3. Priority order

1. Value for Évora
2. Evidence
3. Sustainability
4. Open-source and reuse
5. Engineering quality
6. AIQT dogfood

The higher priority wins when two objectives conflict.

## 4. Scope

The programme may investigate problems affecting:

- residents;
- students;
- workers;
- businesses;
- public-sector organisations;
- associations and IPSS;
- visitors;
- service providers.

Geographic scope is problem-dependent and may include:

- city;
- parish;
- municipality;
- intermunicipal area;
- wider regional context.

The label “Évora Digital” must not force a problem into an incorrect administrative boundary.

## 5. Two programme tracks

### 5.1 Civic Problem Intelligence

The Problem Intelligence track discovers, structures, corroborates, and validates problems before solutions are proposed.

Primary outputs include:

- evidence records;
- problem records;
- stakeholder maps;
- current journeys;
- root-cause hypotheses;
- existing-solution assessments;
- digital-tractability assessments;
- experiment candidates.

### 5.2 Open Civic Data Infrastructure

The Open Civic Data track discovers and evaluates reusable data sources.

Primary outputs include:

- source registry;
- dataset catalogue;
- domain taxonomy;
- candidate canonical entities;
- provenance rules;
- freshness rules;
- licensing and reuse status;
- candidate data contracts;
- possible interoperability or API opportunities.

No centralized datastore or public API is assumed.

## 6. Non-goals during Discovery

Discovery must not prematurely decide:

- first civic application;
- cloud provider;
- database;
- frontend framework;
- API technology;
- microservice architecture;
- authentication model;
- branding;
- AI features.

## 7. Definition of value

Technical outputs are not sufficient evidence of civic value.

Examples of useful outcome measures include:

- time saved;
- unnecessary journeys avoided;
- greater service discovery;
- lower abandonment;
- improved information quality;
- improved accessibility;
- process simplification;
- successful reuse of data by third parties;
- new applications enabled;
- measurable improvements in a validated user journey.

## 8. Sustainability requirement

No civic product should launch without a plausible maintenance model.

Possible operators include:

- Évora Digital community;
- municipality;
- university;
- association;
- business;
- automated source ingestion;
- a combination of the above.

“Maintained indefinitely by one individual” is not a sufficient long-term operating model.

## 9. AIQT role

AIQT is an engineering and governance tool used by the programme.

It may support:

- work-unit execution;
- validation;
- provenance;
- evidence-backed issue generation;
- review;
- release governance;
- context efficiency.

AIQT is not a reason to create a project and must not influence problem priority ahead of civic value.
